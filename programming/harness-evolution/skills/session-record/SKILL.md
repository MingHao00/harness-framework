# 会话记录

本 Skill 只读。只有用户点名调用时才打开 `log/` 和 `Decision/`。不要在对话开始时自动注入这些记录。不要写文件。

## 阅读顺序

1. 先读 `Decision/index.md` 的「当前」段。文件还不存在时，当作当前没有决策。
2. 需要对照当时做了什么时，再读 `log/index.md`，按日期和对话短号打开 `log/YYYY-MM-DD.md` 里对应的那一节。
3. 「已替代」默认不读。只有在判断要不要重开，或用户点名要看时，才打开旧决策文件。旧文件保留，可以检索。

索引一行是一次对话：日期、短号、一句话。不要把历史正文全部读进上下文。

## 工作日志

一天一份，路径 `log/YYYY-MM-DD.md`。一天里的多次对话各占一节，标题带对话短号。时间只记一个北京时间（Asia/Shanghai），到分钟，表示这一节是什么时候写的。不记持续时长，不记毫秒。日期用这个时区的日历日。

每一节的栏目：

- 做了什么
- 改过或读过的路径
- 还没做完的事
- 有没有决策文件（有则是相对路径）
- 试过但行不通的做法及原因
- 下一步的第一个动作

命令和结果只有在会影响下一步时才有一句。空栏是「无」。不抄对话原文，不写密钥。

## 决策记录

一次对话一份，路径 `Decision/YYYY-MM-DD-SHORTID.md`。同一次里的多条取舍在同一份里。每条栏目：

- 定了什么
- 否掉了什么
- 为什么
- 什么新需求出现时应该重开

文件开头有时间和对话短号。若这份替代了旧决策，会写明旧文件名。旧文件不删除。

只把会约束以后实现的选择当决策：定了方案、否掉方案、改了设计文档里的规则、换了依赖或数据格式。来源可以是 Plan 模式、Grilling 讨论，或写代码时的关键取舍。改名、排版、笔误、按已有文档照做不是决策。拿不准就不要当成决策。

## 和新需求冲突

在回复里问用户要不要重开，并说清冲突的是哪一条当前决策。不要改旧文件，不要改 `design/`。

用户拍板后，在回复里写明定了什么、否掉了什么、为什么、什么新需求出现时应该重开，以及被替代的决策文件名。不要自己写 `log/` 或 `Decision/`。Hook 会在对话结束后写入。关窗口时如果写不进去，下次打开项目或新开对话时会补上。任何一次对话里发送「补写工作日志」，Hook 都会立刻补写，包括当前这次。换成别的说法时，Agent 会执行 `node .cursor/hooks/session-record.js --flush`。

## 不要做

- 不要写错误文件
- 不要写密钥
- 不要抄对话原文
- 不要自己写工作日志或决策记录
