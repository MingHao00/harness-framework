# 自进化

这份技能保存 Harness 自进化的约定。话题对上就自己读它。工作日志和决策记录不走这里。

## 改什么

可以改四层：技能、钩子、规则、子代理。

只根据当前这场对话里已经发生的五类事实起草：

- 你纠正过的做法
- 同一份技能、钩子、规则或子代理造成的重复错误
- 这次已经走通、以后应默认采用的办法
- 这场对话里出现过的框架常犯错误
- 这场对话里出现过的框架脚手架

前三类改已经存在的那一份文件。框架常犯错误和脚手架写入 `.cursor/skills/learned/` 里该框架的一份技能；还没有就新建，已有就改那一份，并在 `docs/history/` 追加一条。同一个框架只保留一份。

历史写在 `docs/history/<技能名>.md`。

密钥、令牌、密码不写入技能、钩子、规则、子代理和 `docs/history/`。

## 草稿

每一条草稿写清六件事：改哪一份文件、属于上面哪一类、修改了什么、做了什么改变、成功标准或要跑的测试、来源转录路径。

只有出现这五类事实时才生成草稿。同一场有多条就分条列出。你逐条点头后才写入。你拒绝的条目丢掉，不留半成品。

`auto_approve` 保持 `false`。

改钩子时，跑它已有的 `node --test .cursor/hooks/<相关>.test.js`。改技能、规则或子代理时，以你点头确认的那条成功标准为准，不自动再叫模型打分。检查失败就撤回这次写入，文件保持原样。

## 何时起草

四句话是同一条路：「自进化」、`/evolve`、「抽取经验」、`/learn`。都是立刻为当前对话起草，并在回复里给你看。

用户消息不少于 10 条的会话，结束时自动准备草稿。短对话跳过。条数由 `config.json` 的 `min_session_length` 决定。

自动起草走会话记录已经在用的模型接口，不另指定模型。模型失败时只留下转录路径，下一场再抽。

## 钩子

约定是：会话结束时先写工作日志，再抽这份草稿。两边互不影响。自进化不写工作日志，也不写决策记录。

`sessionEnd` 先跑会话记录，再调用 `node .cursor/hooks/run-legacy.js evaluate-session.js`。够长时，这个脚本用会话记录同一条模型接口把草稿写入本目录的 `pending.json`，`status` 为 `draft`，`items` 是草稿列表。它不改技能、钩子、规则和子代理。模型失败时 `status` 为 `pending`，只留转录路径。没有合格事实时不留下这份文件。

下一场开始时，`draft` 把 `items` 逐条给你看；只有转录路径时再按本约定抽一次。你同意并写入之后，删掉 `pending.json`。你整份拒绝时也删掉。

## 配置

`config.json` 的 `auto_approve` 保持 `false`。`learned_skills_path` 是 `.cursor/skills/learned/`。`patterns_to_detect` 对上上面五类事实。
